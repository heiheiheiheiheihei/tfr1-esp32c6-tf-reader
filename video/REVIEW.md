# 审片记录 · TFR-1 介绍片

审的是 `renders/tfr1-intro.mp4`（1920×1080 / 30 fps / 1620 帧 / 54.0 s / H.264 1.45 Mbps + AAC 48 kHz，
9.4 MB）。
方法：`check` 全绿后，用 `snapshot --review` 抓每个场景的起点、中点和 8 个接缝
（每缝 5 帧，±0.2 s），逐张看；再用 `ffprobe` + `ebur128` 量声音。

## 通过了什么

- `hyperframes check`：lint / runtime / layout / motion / contrast / audio 全部 0 error。
  craft 18 条 warning，全部是"字号低于 28 px"和"短句停留短于 0.5 s + 0.3 s/词"，
  逐条处理过一遍（见下）。
- 8 个接缝都有画面上的起因：划掉 → 规格表；✗ → 通路图；通路（缩放）→ 扇区点阵；
  点阵 → 帧；帧（缩放）→ 终端；终端 → 挂载；截屏 → 实拍；实拍 → 声明。
- 每个镜头内至少一处运动：扇区点亮与放大、计数、逐字打字、页面 READY→ONLINE 切换、
  数字 0.00→0.21、实拍推镜。
- 事实全部可溯源：数字来自真机 `--info` / `--bench 4` 和 `host/tfreader_host.py` 源码；
  终端里的每一行都是脚本真的会打印的字符串；UI 是 172×320 的真截图，照片是原片。
  没有一格是重画的 UI。

## 改过的（第一版 → 这一版）

1. 首帧太黑太空：卡放大到 366×498、字 132→148 px、整列下移。首帧必须能当封面。
2. `✗` 用的是字体里的 U+2717，落到系统字体后大小不可控 → 改成两根 CSS 红线，
   尺寸在自己的控制里。
3. `s3` 的五节点图挤在画面下三分之一、上半空 → 节点下移到 y 600，总线自左向右画。
4. `s4b` 的协议帧是一条细带 → 盒子 104→176 px 高、字段值 27→34 px，整组下移到视觉中心。
5. 终端面板 600 px 高、只有 4 行字 → 收到 420 px，字号 30→36 px。
6. `s4c` / `s4d` 一开始几乎空屏（只有 `$ ./` 几个字）→ 改成**同一个终端会话的回滚**：
   上一场的输出留在屏幕上，这一场接着打字。既补了密度，也把两场缝在同一台机器上。
7. 实拍照片与深色底之间的硬边 → 给照片本身加 `mask-image` 做左缘渐隐，不再有竖切缝。
8. 片尾字标没有真的居中（字标在 760 px 的盒子里左对齐）→ 盒子收到 584 px，整组居中。
9. 音乐 −20.4 LUFS，偏小 → bed 音量 0.62 → 1.0，目标 −16 LUFS（见下面的实测）。
10. 只有音乐没有动作声 → 补 3 个合成音效，只贴在有起因的画面上：
    两个 `✗`、扇区点亮、payload 落位（tick）、进入终端与切实拍（whoosh）、
    READY→ONLINE（click）。

## 仍然留着的问题（明知未解决）

- **未在手机上实看**。字号 28 px 的底线是按 1080 高度算的；B 站手机端缩放后
  终端里 30–31 px 的行会偏小。已知，不假装修过。
- craft 里剩下的"停留时间短"警告，多数是快剪段的副标题（1.3–2.0 s）。
  这是刻意的节奏，不是漏改；代价是有人可能看不及。
- 字幕只有画面内嵌，没有 SRT。要 CC 字幕得另做一份。
- **合成音乐听感没人真的听过**：只量了 −16.9 LUFS / −1.5 dBTP（`ebur128`），
  节奏点（38.5 s 的 impact、48 s 的收束）是按时间轴写的，不是我耳朵调的。
  这是这版最大的未验证项。
